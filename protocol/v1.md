# Protocol version 1

## State root and transport

The CLI injects `GDBG_STATE` into the Godot process. Both sides use:

```text
<GDBG_STATE>/debug/ipc/command
<GDBG_STATE>/debug/ipc/result
<GDBG_STATE>/debug/ipc/temp_script.gd
```

The CLI writes one `command` file and waits for one `result` file. The runtime
consumes the command; the CLI consumes the result. Commands are serialized, so
version 1 does not define concurrent request identifiers.

## JSON command

```json
{
  "protocol": 1,
  "cmd": "input",
  "args": {
    "op": "tap",
    "action": "interact"
  }
}
```

`cmd` is required. `args` is an array for project console commands and an
object for bridge-owned commands. An optional `screenshot` object asks the
runtime to schedule a screenshot after a console command.

Bridge-owned commands in version 1 are:

- `screenshot`: capture one or more viewport images.
- `fetch`: retrieve an asynchronous capture by `capture_id`.
- `input`: list, press, release, tap, or hold Godot input actions.

All other commands are joined as console text and delegated to the project's
`DebugBridgeHost`. This is the extension boundary used by game-defined console
modules.

## JSON result

Successful result:

```json
{"protocol":1,"result":"pong"}
```

Error result:

```json
{"protocol":1,"result":null,"status":"error","message":"Unknown input action: jump"}
```

Asynchronous captures may return `capture_id`, `status: "pending"`, and a
human-readable `progress` value before becoming ready.

## Plain text compatibility

A command file that does not begin with `{` is treated as console text. A
non-JSON result is returned verbatim. This compatibility path is unversioned;
new integrations should use JSON envelopes.

## Script staging

`gdbg debug script file.gd` writes the script to `temp_script.gd`, then sends
the project console command `script`. The host project decides whether and how
to execute staged scripts; GDBG does not grant additional sandboxing.
